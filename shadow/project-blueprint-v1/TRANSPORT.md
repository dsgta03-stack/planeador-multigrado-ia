# Provider Transport Contract != ProjectBlueprintV1 Domain Contract

`transport-schema.mjs` builds BLUEPRINT_TRANSPORT_V1 from a fresh copy of the domain schema. It retains types, object properties, required keys, array items, nullable alternatives, version markers, DRAFT status, null gate_result and the exact requested session count. It does not embed dynamic hash/resource/operation enums, regexes, length constraints, numeric bounds, uniqueness or semantic rules. The full generation schema remains in the prompt; the full versioned domain contract remains authoritative locally.

Passing Google's transport schema only means that a candidate can be parsed and inspected. The unchanged local domain validation and deterministic Gate run before semantic review. Semantic review uses the same Blueprint/source hash. No schema or transport function can issue approval. The transport schema does not mutate schemas/ProjectBlueprintV1.json or gate.mjs.

The shadow Edge Function authenticates the existing expiring machine identity before invoking Google. Reception of Google's response, extraction of the first candidate's non-thought text, and strict JSON.parse are separate operations. A 200 response whose candidate is not valid JSON returns PROVIDER_OUTPUT_INVALID_JSON with provider_status=200, model, finish_reason, usageMetadata/usage, latency_ms, text_length, parse_error and approximate error position when available. Raw text is retained up to 100,000 UTF-16 code units; text_truncated explicitly identifies longer responses. Known credentials are redacted defensively from diagnostics. No raw candidate is logged; the authenticated runner persists it in shadow evidence.

No JSON5, tolerant parser or automatic text repair is used. Invalid JSON is neither PROVIDER_UNAVAILABLE nor a pedagogical rejection. It is not retried. The orchestrator preserves prior revisions if present and creates no new revision or repair_count for failed transport. Only a successfully received pedagogical repair candidate advances that counter. Provider 400 messages are preserved in full (except credential redaction). Existing 429/503 handling and the global sequential eight-second limiter remain unchanged.

The live reviewer, LOCAL_EVIDENCE_V1_LITERAL_QUOTES_R2, and its previously validated 22/22 fixtures are unchanged. Tests in tests/transport.test.mjs cover strict parsing, raw evidence, bounded/redacted diagnostics, one attempt/no repair for invalid output, the representability of a valid domain Blueprint, rejection by the full domain/Gate despite transport acceptance, and failed repair transport preserving revision 1.
